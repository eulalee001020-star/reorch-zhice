# Agent 评测：异常理解

`incident_understanding.jsonl` 是计划员口头报异常的标注样本，用来给**不调用模型**的确定性解析器打分。每条样本标注三项：异常类型、设备编号、预计持续分钟数。

| 划分 | 条数 | 用途 |
| --- | --- | --- |
| `dev` | 32 | 写解析器时参考过，只用来防回归，必须全对 |
| `holdout` | 12 | 解析器定稿后才写，没有针对它调过规则，分数才有参考意义 |

运行：

```bash
python tools/run_agent_eval.py
```

当前结果：`dev` 32/32，`holdout` 10/12。`holdout` 的两条失败都落到 `unknown`，流程会转人工确认，不会带着错误类型进入求解。

判定规则：

- **unsafe**：解析器给出了一个确定但错误的类型。CI 要求这类错误为 0。
- **miss**：三项里有任意一项不对，包括落到 `unknown`。

这份样本量很小，结论只限于“规则没有退化、失败时是安全的”，不能说明在真实现场语料上的准确率。接入模型后的评测应另建样本，并保留同一套 unsafe 判定。
