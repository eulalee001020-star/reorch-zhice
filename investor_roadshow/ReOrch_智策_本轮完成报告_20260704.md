# ReOrch 智策本轮完成报告

版本：2026-07-04

## 本轮目标

围绕“企业合作后逐步不再依赖其他排产系统”的长期目标，本轮没有直接堆完整 APS 页面，而是按第一性原理先补可信性地基：

1. 真实客户数据能否读懂。
2. 现场约束能否被人工确认并编译。
3. 历史异常能否被 replay 验证。
4. shadow mode 能否只读采集计划员反馈。
5. AI 调用能否记录成本、latency、fallback 和 guardrail。

## 当前能证明什么

- 能从 P0 客户样例数据进入 canonical dataset 和 `ScheduleSnapshot`。
- 能把人工确认的现场约束编译为排产输入。
- 能阻断未发布、未 replay 通过、或缺人工确认的 AI 规则候选。
- 能用历史接受方案对候选方案做可比性评估。
- 能在 shadow mode 下记录计划员反馈且不产生写回。
- 能统计 AI 调用的 token、latency、fallback、guardrail 和成本估算。

## 当前不能证明什么

- 不能证明已经完成客户生产部署。
- 不能证明无人值守自动排产安全。
- 不能证明现有 replay 结果等同客户生产 ROI。
- 不能证明已可全面替代金蝶、用友、成熟 APS 或客户现有排产系统。
- 不能证明所有行业约束、物料、人员、工装、外协和跨车间能力已经补齐。

## 下一步必须补证据

1. 用真实客户导出的历史工单、工序、资源、排程快照和异常日志替换 P0 样例包。
2. 至少回放 10-30 条真实历史异常。
3. shadow mode 运行 2-4 周，记录接受、微调、拒绝、override 和执行反馈。
4. 完成 sandbox 人工确认 dry-run 回写、幂等、防重复提交和回滚演练。
5. 拿到 1 家付费 PoC 或明确试点协议。
